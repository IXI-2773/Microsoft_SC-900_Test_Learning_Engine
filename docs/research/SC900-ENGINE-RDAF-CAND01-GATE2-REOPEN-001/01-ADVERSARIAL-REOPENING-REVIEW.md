## Critical adversarial finding — historical prior

The original portability review says the SY0-701 historical prior is `PLAUSIBLE_BUT_UNPROVEN` and explicitly blocks positive closure until direct SC-900 evidence exists.

CAND-01R2 nevertheless carries the historical learner profile as a SEED prior for starting emphasis.

That creates a circular dependency if Gate 2 simultaneously requires direct SC-900 outcome evidence before authorizing the implementation needed to collect clean SC-900 outcomes.

The correct response is not to lower the portability standard and not to manufacture outcomes.

The response is to remove the unproven cross-exam prior from the load-bearing initial implementation.

## Why the correction is bounded

RRC-1 itself does not require the Security+ prior:

- REPAIR uses current SC-900 active-weak state;
- REVIEW uses current SC-900 due state;
- COVERAGE uses current SC-900 blueprint deficit;
- service order is deterministic;
- confidence is excluded from class membership;
- response time is excluded from class membership;

The cross-exam prior is therefore an optional cold-start hypothesis, not necessary architecture for the first serious SC-900 comparison.

## Other adversarial attacks

### Bank independence and measurement power

29 PROBE questions are not treated as 29 independent units. The design reports 7 independent semantic families. This is limited but sufficient to instantiate a serious first local measurement protocol; it is not sufficient to claim general population validity.

### Probe objective coverage

Seven objectives are absent from PROBE. This prevents objective-complete effectiveness claims. It does not invalidate the primary design-time held-out endpoint if the limitation is explicit and policy claims remain restricted to the observed probe support.

### RRC-1 thresholds

No maximum overdue days, minimum COVERAGE share, acceptable starvation rate, or dominance cut is invented. Gate 2 requires measurability and a future testable contract, not fictitious calibration.

### Runtime isolation

No runtime consumer exists. This is expected at Gate 2. The future implementation must use the Task-7 shared eligibility boundary before candidate construction, derived-state creation, restore, render, history, analytics, and export exposure. Gate 3 must prove this.

### One-learner causal limits

The planned comparison remains N-of-1 and vulnerable to time/order/outside-study effects. The design does not claim those disappear. It predeclares reporting/control obligations and prohibits generalizing a local result into population efficacy.
