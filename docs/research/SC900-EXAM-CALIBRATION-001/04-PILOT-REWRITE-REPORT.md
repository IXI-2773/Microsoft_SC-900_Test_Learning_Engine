# Pilot rewrite report

A stratified pilot of 24 items was rewritten first, then the same rubric was applied to the remaining flagged set.

Pilot coverage: all four domains; Core, Applied, and Stretch candidates; direct concept, scenario, service selection, and misconception forms.

## Before / after examples

Only original bank items are shown. No external-book text.

### 1. Zero Trust least privilege (`sc900_mlc_q201`)

Before: a program already verifies every sign-in, yet standing full-access roles remain; the learner must diagnose the missing principle.

After: one requirement — users should receive only the permissions required for their work — and neighboring Zero Trust principles as options.

Tested decision unchanged: least privilege. Tier: FUNDAMENTALS_CORE.

### 2. Successful sign-in is not blanket authorization (`sc900_mlc_q205`)

Before: MFA success plus a colleague's false claim, then "what is wrong with that claim?"

After: the same scenario asks which process determines what the contractor may access. Options are authentication, authorization, federation, and Conditional Access.

Tested decision unchanged. Tier: FUNDAMENTALS_CORE.

### 3. PIM eligible assignment (`sc900_mlc_q241`)

Before: auditor question plus extra standing-privilege story.

After: one PIM idea — eligible until activation — with neighboring Entra-governance distractors.

### 4. SIEM/SOAR pairing (`sc900_mlc_q111`)

Stem kept (the pairing is the tested decision). Joke distractors (certificates, DLP/WAF, replacing Entra ID) replaced with neighboring wrong pairings. Tier: FUNDAMENTALS_APPLIED.
